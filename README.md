# AlphaMining Benchmark

Portable evaluation harness for LLM-based alpha-mining systems. Accompanies the NeurIPS 2026 paper *"What Do LLM Alpha-Mining Agents Add? Evaluating Incremental Factor Value and Selection Metrics"*.

## Architecture

The pipeline has two independent components:

**Generator** — one Docker container per system. Each container receives a read-only dev data bundle and a write directory, runs the system's native factor mining loop, then converts the workspace output into a standard `candidates.parquet` file via a thin adapter.

**Evaluator** — plain Python. Loads `candidates.parquet` files from any number of systems, selects at most 50 factors, combines them with Alpha158 via Ridge regression, runs a Qlib backtest on the sealed test period, and writes `metrics.json`.

```
systems/
  alphaagent/    Dockerfile  build.sh  entrypoint.sh  adapter.py
  quantaalpha/   Dockerfile  build.sh  entrypoint.sh  adapter.py
evaluator/
  selector.py    factor selection (standalone RankIC or marginal increment)
  run_eval.py    Qlib backtest + metrics output
orchestrator/
  run_experiment.py   launches containers, collects outputs, calls evaluator
configs/
  universes/     csi500.yaml  csi300.yaml  sp500.yaml
  backbones/     deepseek.yaml  openai.yaml
```

## Data bundles

Each universe requires a Qlib-format data directory. The same directory serves both the dev window (accessible to generators) and the test window (loaded only by the evaluator). Test labels are never mounted into system containers.

| Universe | Qlib data path | Instruments (train) | Instruments (backtest) |
|---|---|---|---|
| CSI500 | `~/.qlib/qlib_data/cn_data` | `csi500_full` (1,803 tickers, 2016–2025) | `csi500` (point-in-time) |
| CSI300 | `~/.qlib/qlib_data/cn_data` | `csi300_full` | `csi300` |
| S&P 500 | `~/.qlib/qlib_data/us_data` | `sp500_full` (858 tickers, 2016–2025) | `SP500` |

`csi500_full` and `sp500_full` are static instruments files (all historical constituents, single date range spanning the full period) that eliminate survivorship bias during training while keeping point-in-time membership for backtest execution. They live alongside the standard instruments files in each Qlib data directory and are generated by the data pipeline scripts in `DataPipeline/`.

## Setup

### 1. Build system images

```bash
# from alphamining_benchmark/
bash systems/alphaagent/build.sh
bash systems/quantaalpha/build.sh
```

`build.sh` copies the system code from the adjacent repo into a temporary Docker build context alongside the adapter and entrypoint, then runs `docker build`. To override the system repo path:

```bash
SYSTEM_REPO=/path/to/system/repo bash systems/alphaagent/build.sh
```

### 2. Set API credentials

```bash
export LLM_API_KEY=sk-...
export LLM_API_BASE=https://api.deepseek.com/v1   # or openai, qwen, etc.
```

For self-hosted open-weight models (Qwen, DeepSeek), run a vLLM server with an OpenAI-compatible endpoint and point `LLM_API_BASE` at it. All containers in an experiment share the same endpoint, which enforces the common-backbone requirement.

### 3. Run an experiment

```bash
python orchestrator/run_experiment.py \
    --systems alphaagent quantaalpha \
    --universe csi500 \
    --backbone deepseek-v3 \
    --runs 5 \
    --loop-n 10 \
    --dev-data-dir  /path/to/your/qlib_data/cn_data \
    --test-data-dir /path/to/your/qlib_data/cn_data \
    --output-dir    /path/to/your/results/exp_001 \
    --budget-usd    100
```

The orchestrator launches one container per `(system, run)` pair sequentially, collects `candidates.parquet` from each, then calls the evaluator. Results land in `--output-dir`:

```
results/exp_001/
  experiment.json          run metadata
  alphaagent/run00/candidates.parquet
  alphaagent/run01/candidates.parquet
  ...
  quantaalpha/run00/candidates.parquet
  ...
  metrics.json             ΔRankIC, ΔNet IR, base/enhanced breakdown
  summary.json             run counts + metrics combined
```

### 4. Run the evaluator standalone

If you already have `candidates.parquet` files and only want to (re-)evaluate:

```bash
python evaluator/run_eval.py \
    --candidates /path/to/results/alphaagent/run00/candidates.parquet \
                 /path/to/results/quantaalpha/run00/candidates.parquet \
    --data-dir   /path/to/your/qlib_data/cn_data \
    --universe   csi500 \
    --output     /path/to/results/metrics.json \
    --selector-mode standalone \
    --max-factors   50
```

`--selector-mode marginal` runs greedy forward selection by marginal RankIC increment over Alpha158 (more accurate, slower). `standalone` selects by dev-period standalone RankIC (fast default).

## Container interface

Every system container exposes the same interface regardless of what runs inside it:

| Hook | Type | Purpose |
|---|---|---|
| `/data/dev` | read-only mount | Qlib dev data bundle (train 2016–20 + val 2021–22) |
| `/output` | write mount | adapter writes `candidates.parquet` here |
| `UNIVERSE` | env var | `csi500`, `csi300`, or `SP500` |
| `BACKBONE` | env var | LLM model name (informational, passed to adapter) |
| `LOOP_N` | env var | number of mining iterations |
| `BUDGET_USD` | env var | cost cap in USD |
| `LLM_API_BASE` | env var | LLM endpoint URL |
| `LLM_API_KEY` | env var | LLM API key |

## `candidates.parquet` schema

| Column | Type | Description |
|---|---|---|
| `factor_name` | string | unique factor identifier |
| `formula` | string | mathematical formula |
| `code` | string | Python implementation |
| `dev_rankic` | float | mean cross-sectional rank IC on dev period (2021–22) |
| `dev_ic_ir` | float | IC information ratio on dev period |
| `iteration` | int | mining round that produced this factor |
| `generation_cost_usd` | float | LLM API cost for this factor (if tracked) |
| `system` | string | generating system name |
| `backbone` | string | LLM backbone used |
| `universe` | string | target universe |
| `valid` | bool | factor code executed without error |
| `error` | string | error message if `valid=False` |

## Adding a new system

1. Create `systems/<system_name>/`
2. Write `adapter.py` — reads whatever the system writes to its workspace, outputs `candidates.parquet` with the schema above
3. Write `entrypoint.sh` — runs the system, then calls `adapter.py`
4. Write `Dockerfile` — installs the system's deps, copies adapter and entrypoint
5. Write `build.sh` — assembles build context and runs `docker build`
6. Add `"<system_name>": "alphamining/<system_name>:latest"` to `SYSTEM_IMAGES` in `orchestrator/run_experiment.py`

## Evaluation protocol (paper)

- **Train**: 2016–2020 &nbsp;|&nbsp; **Val/feedback**: 2021–2022 &nbsp;|&nbsp; **Test (sealed)**: 2023–2025
- **Label**: `open[t+6] / open[t+1] - 1` (five-day forward return from next open)
- **Primary metric**: library-level ΔRankIC — mean daily RankIC of Alpha158 + selected factors minus Alpha158 alone, paired by date over the sealed test window
- **Secondary metric**: ΔNet IR — enhanced minus base portfolio net IR at 10 bps one-way cost
- **Portfolio rule**: long-only Top50/Drop5 at next open
- **Universe for training**: full historical constituents (`csi500_full` / `sp500_full`)
- **Universe for backtest execution**: point-in-time index membership (`csi500` / `SP500`)
- Test window is read once by an independent evaluator after all generation and selection is complete
